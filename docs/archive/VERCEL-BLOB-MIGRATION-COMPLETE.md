## 🎯 Problem Solved

**Original Issue:**
- Image uploads failing with 400 error on Vercel
- Black preview boxes for uploaded images
- Local filesystem storage incompatible with Vercel's serverless environment

**Root Cause:**
- Vercel has a **read-only filesystem** in production
- Cannot write files to `public/uploads/` directory
- Missing `BLOB_READ_WRITE_TOKEN` environment variable

---

## 📝 Code Changes Summary

### Before (Local Filesystem - ❌ Fails on Vercel)

```typescript
import { writeFile, mkdir } from 'fs/promises';
import path from 'path';

export async function saveUploadedImage(...) {
  const uploadDir = path.join(process.cwd(), 'public/uploads/images', entityType);
  await mkdir(uploadDir, { recursive: true }); // ❌ Fails: read-only filesystem
  await writeFile(filePath, buffer); // ❌ Fails: cannot write
}
```

### After (Vercel Blob - ✅ Works on Vercel)

```typescript
import { put, del } from '@vercel/blob';

export async function saveUploadedImage(...) {
  const blob = await put(blobPath, file, {
    access: 'public',
  }); // ✅ Uploads to Vercel Blob cloud storage
  
  const filePath = blob.url; // ✅ Public HTTPS URL
}
```

## 💡 Key Learnings

### Vercel Serverless Constraints

1. **Read-Only Filesystem:**
   - Cannot write files to local disk
   - Must use cloud storage (Blob, S3, etc.)

2. **Environment Variables:**
   - Must be set in Vercel Dashboard
   - Auto-generated for Vercel services (Blob, Postgres, etc.)

3. **Deployment:**
   - Use `--force` flag to clear cache
   - Check logs: `npx vercel logs`

### Best Practices

1. **Storage:**
   - ✅ Use Vercel Blob for file uploads
   - ✅ Store URLs in database, not file paths
   - ✅ Set `access: 'public'` for publicly accessible files

2. **Error Handling:**
   - ✅ Provide detailed error messages
   - ✅ Log upload progress for debugging
   - ✅ Validate files client-side AND server-side

3. **Cleanup:**
   - ✅ Remove old data when migrating storage
   - ✅ Use scripts for batch operations
   - ✅ Delete scripts after one-time use
