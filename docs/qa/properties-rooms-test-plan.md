# QA test plan — Properties / Rooms

**Routes:** `/admin/properties`, room detail `/admin/rooms/[id]`  
**Source:** `AddBuildingModal.tsx`, `AddRoomModal.tsx`, `EditRoomForm.tsx`, `POST/PUT/DELETE /api/buildings`, `POST/PUT/DELETE /api/rooms`, `POST /api/rooms/bulk`, `POST /api/rooms/[id]/assign`  
**Training job:** [add-unit.md](../training/add-unit.md)

Priority: **Critical** = occupancy / rates / data integrity. **Important** = validation and list tools. **Nice-to-check** = convenience UI.

| # | Scenario | Steps | Expected result | Priority |
| --- | --- | --- | --- | --- |
| 1 | Happy path: create Balibago-style building and a ₱4,800 studio | Properties → **Add**. **Building name** `QA Annex Angeles {stamp}`. **Building type** Residential. **Region** + **City**. **Create building**. Select it → **Add Room** → room `QA-1`, type Studio, **Monthly rate (₱)** `4800` → **Create room**. | Toast **Building created successfully**. Toast room created. Building appears in the left list; room shows ₱4,800. | Critical |
| 2 | Required field validation: building name, region, and city | **Add** → leave **Building name** empty → **Create building**. Then fill name only and submit. | HTML5 `required` on `#name`, `#region`, `#city`. Submit is blocked (`validity.valueMissing`). API, if reached, returns **Missing required fields** / **Name, city, and region are required**. | Critical |
| 3 | Invalid input: negative monthly rate is blocked in the UI only | **Add Room** → fill room number → **Monthly rate (₱)** `-100` → **Create room**. | Input has `min={0}`; `validity.rangeUnderflow` is true and the room is **not** created from the form. | Important |
| 4 | No validation found — flag as bug: API accepts a negative monthly rate | After login, `POST /api/rooms` with `monthlyRate: -100` on a QA building (not used by the office form). | **Unexpectedly permissive:** API does **not** validate rate. Create currently succeeds (201 / **Room created successfully**). Flag: server should reject negatives the same way the UI does. | Important |
| 5 | Edit/update an existing building and room | Open the QA building → **Edit property** → **Update building**. Open the room → **Edit Room** → set **Monthly Rent (₱)** to `5200` → **Save Changes**. | Toasts **Building updated successfully** and **Room updated successfully**. Rent field shows `5200`. | Critical |
| 6 | Delete/deactivate a building: soft delete, related rooms are not cascade-removed | Create a throwaway building + room. **Delete property** → type `DELETE` → **Delete Building**. Refresh. GET `/api/rooms?buildingId=` still returns the room row (`is_active` may be unchanged). | Building disappears from the Properties list (`is_active = false`). Success **Building deleted successfully**. UI copy claims rooms/assignments/images are permanently removed — **they are not**; this is a product/docs mismatch to flag. Do **not** delete Balibago or Villasol. | Critical |
| 7 | Duplicate building names are allowed — flag as bug | Create two buildings with the same name `QA Duplicate Annex`. | Both create succeed. No unique constraint on `buildings.name`. **Unexpectedly permissive** if the office expected one Balibago. | Nice-to-check |
| 8 | Duplicate room number in the same building | Create room `QA-DUP` once, then **Add Room** with the same number again (or `POST /api/rooms` a second time). | Bulk API returns **409** `These room numbers already exist in this building`. Single `POST /api/rooms` has **no app-level check** and typically **500 Failed to create room** (DB unique). Flag: single-create should return the same 409 as bulk. | Important |
| 9 | Data persists correctly after a page refresh | Create building + room, then reload `/admin/properties`, select the building, open **Rooms**. | Building still in the list; room number and ₱4,800 still show. | Critical |
| 10 | Permission check: unauthenticated and tenant users cannot open Properties | Open `/admin/properties` with no session. Then sign in as a tenant and open the same URL. | Both land on `/auth/signin`. Admin (and leftover `caretaker`, normalized to admin) can load the page. There is **no separate caretaker office role**. | Critical |
| 11 | Search properties by name | Left list **Search** (`aria-label` **Search properties**). Type the unique QA building name, then a nonsense string. | Unique name shows that building. Nonsense shows **No properties found**. | Important |
| 12 | Sort properties | Change **Sort** (`#property-sort`) to **Name Z–A**, then **Most vacant**. | Select value updates; list remains visible (client-side sort). | Nice-to-check |
| 13 | Filter properties by occupancy | **Filter** (`#property-filter`) → **Has vacant rooms**, then **Fully occupied**. | List filters client-side. A building with the new vacant QA room appears under **Has vacant rooms**. | Important |
| 14 | Rooms tab search and status filter | On the QA building **Rooms** tab, search the room number; set **Status** to **Vacant** then **Occupied**. | Search matches the room. Vacant filter shows it; Occupied hides it until assigned. | Important |
| 15 | Assigning a second tenant to an occupied room replaces the prior lease | Via API: assign tenant A, then assign tenant B to the same QA room. | Second assign **succeeds**. Room stays occupied by B. A’s assignment is terminated (history kept). HTTP route does **not** return “Room is already occupied” (that string exists only on an unused helper). Flag if the office expected a hard block. | Critical |
| 16 | Export / print on Properties | Look at Properties list and room tab for export/print. | **No export or print** on this module (training “Also on this page”). | Nice-to-check |
